# Kairos v1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add true exposure, thesis check, evening refresh and side-by-side compare to Kairos.

**Architecture:** Backend: two nullable columns on `lists` (`shares`, `thesis`), a new `services/exposure.py` with `GET /api/exposure`, an optional `thesis_check` in the AI summary fed by the stored thesis, and a second scheduler slot that runs a readings-only job. Frontend: new Exposure and Compare views, a "Your reason" card and ⚠ markers, all within the redesign-A layout.

**Tech Stack:** unchanged from v1 (FastAPI/uv/pytest; React/Vite/TS/TanStack Query/Zod/Zustand/Vitest/msw/lightweight-charts).

**Spec:** `docs/superpowers/specs/2026-11-02-kairos-v1.1-design.md` (and the v1 spec it builds on).

## Global Constraints
- Share counts and portfolio values never appear in AI prompts (test-enforced). The thesis sentence is the only new prompt input, for its own ticker only.
- Exposure shows ETF remainder beyond top holdings as "Rest of funds (beyond top 10 holdings)"; never redistribute it.
- No buy/sell wording anywhere new.
- Thesis ≤ 200 chars, trimmed; shares finite and ≥ 0 (0/null clears). Ticker input normalized via `normalize_ticker`.
- Evening refresh default `EVENING_REFRESH_TIME=21:00`, empty disables; readings only (no Discover, no outcomes). Morning slot due 07:00 → next 21:00; evening slot due 21:00 → midnight.
- ETF holdings/sector cache: 6 hours, in memory.
- Older stored payloads must still load (new fields optional).
- Conventional commits; branch `feat/v1.1`; no AI attribution.

## Review Focus
1. **Holding with no price or no reading yet** (just added, Yahoo down): exposure excludes it from totals and lists it in `missing_prices`, no 500. Test in Task 2.
2. **ETF with no top-holdings data**: whole ETF value goes to "rest of funds"; sectors to "Unknown" if missing. Test in Task 2.
3. **Thesis edited after the last reading**: UI shows "Refresh to check your updated reason" (compares `thesis` to reading's `thesis_checked`). Test in Task 6.
4. **Prompt-injection-ish or overlong thesis** (newlines, quotes, 500 chars): API trims/limits to 200 → 422 over limit; prompt quotes it as data. Tests in Tasks 1 and 3.
5. **Compare with one stock and one ETF / same ticker twice**: rows show "—" where not applicable; same ticker → message "Pick two different tickers". Test in Task 7.

### Task 2: Exposure service and endpoint

**Files:** Create `backend/kairos/services/exposure.py`; Modify `backend/kairos/adapters/prices.py` (add `get_sector_weightings`), `backend/kairos/api/routes.py`; Test `backend/tests/services/test_exposure.py`, `backend/tests/api/test_exposure_api.py`

**Interfaces — Produces:**
- `prices.get_sector_weightings(etf) -> tuple[dict[str, float], SourceStatus]` from `funds_data.sector_weightings`.
- `exposure.SECTOR_NAMES: dict[str, str]` mapping Yahoo fund keys (`realestate`, `consumer_cyclical`, `basic_materials`, `consumer_defensive`, `technology`, `communication_services`, `financial_services`, `healthcare`, `industrials`, `energy`, `utilities`) to display names (`Real Estate`, `Consumer Cyclical`, …).
- `async exposure.compute_exposure(conn, now) -> dict` with shape from the spec §3 API. Price: latest reading price if reading age < 24h else `get_info` (`regularMarketPrice` or `previousClose`). Kind: latest reading `kind` else `info.quoteType == "ETF"`. ETF holdings & sectors via a 6h in-memory cache (`_cache: dict[(kind, ticker), (expires_at, value)]`). Weights are fractions of total value. `underlying` sorted desc, top 15; `via` maps ETF → weight. `rest_of_funds` = Σ over ETFs of `etf_value × (1 − Σ top weights) / total`.
- Route `GET /api/exposure`.
