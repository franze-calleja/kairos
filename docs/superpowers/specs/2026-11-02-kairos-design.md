# Kairos — Design

*Date: 2026-11-02 · Status: draft for review*

Kairos (Greek: "the right moment") is a personal, AI-powered stock and ETF research assistant. It reads news, filings and online discussion about a ticker and produces a short, sourced **reading**: a lean (bullish / neutral / bearish) with a confidence level, what's driving it, the bull and bear case, and the price context — so the owner can judge whether *now* is a reasonable moment to buy or add.

It is a research aid, not a trading bot and not a price predictor.

Items marked **(owner)** were decided by the owner. Items marked **(designer's call)** were chosen by the designer and can be revisited. Unmarked items are descriptive.

---

## 1. Intent and the why

The owner is a long-term retail investor holding broad-market ETFs and a few individual stocks, buying through a retail broker app. Ticker ideas come mostly from **TikTok, Reddit and the broker app**, and those sources conflict, mix hype with real news, and take time to cross-check.

Kairos exists to answer three recurring questions quickly and with evidence:

1. **Holdings check** — "Has anything meaningful changed for what I own, and is now a reasonable time to add more?"
2. **Hype check** — "I saw this ticker on TikTok/Reddit/my broker app. Is there real substance behind it, or is it buzz?"
3. **Discover** — "What else is worth a closer look?"

**What success looks like:** the owner opens Kairos instead of hopping between TikTok, Reddit and news sites; gets a reading they can verify via linked sources; and, over months, can see from the track record whether Kairos's leans are worth trusting.

## 2. Goals, non-goals, anti-goals

### Goals (v1)
- Dashboard with the **sidebar layout** (owner): holdings, watchlist and Discover suggestions in a left sidebar; selecting a ticker opens its full reading on the right; a search bar on top runs an on-demand reading for any ticker (the hype check).
- Readings for **US stocks and US ETFs**.
- The five v1 features in §5 (owner agreed to the split).
- Runs locally on the owner's Mac via Docker Compose, plug-and-play (owner).
- Uses free data sources and the **Gemini API free tier** (owner: free sources; designer's call: Gemini over Grok — see §7).

### Non-goals (v1)
- Placing trades, broker integration, or portfolio syncing.
- Intraday / day-trading signals.
- Numeric price targets ("NVDA will be $200 on Friday").
- Multi-user accounts, sign-up, or public hosting.
- Discord/email summaries, alerts, chat, compare, thesis tracking, exposure view (all **later** — §6).
- Scraping TikTok (no usable free/official access; the owner brings TikTok tickers to the search bar).

### Anti-goals (would make it a failure even if it "works")
- **Confident-sounding output without evidence.** Every claim in a reading must link to a source; when evidence is thin, Kairos says "not enough signal" rather than guessing.
- **The AI inventing numbers.** Prices, averages, valuation figures and hype signals are computed in code from data, never generated by the LLM.
- **Presenting the lean as a buy/sell instruction.** The UI frames it as one input to research.
- **Heavy to run.** No local ML models, no Postgres, no message queues, no Kubernetes. One small container.
- **Silent breakage.** If a data source fails (e.g., yfinance changes), the reading shows what's missing rather than quietly degrading.

## 3. Constraints
- **Cost:** free tiers only. No paid APIs required to run.
- **Weight:** lightweight on a 16 GB Apple Silicon Mac; later on a shared Hostinger VPS that already runs other production workloads (Dokploy). Keep memory and CPU modest.
- **Packaging (owner):** containerized, plug-and-play: copy `.env.example` → `.env`, add keys, `docker compose up`, open the browser.
- **Hosting order (owner):** Mac first, VPS later. Design must not block a later VPS move (config via env, data in a mounted volume, single port behind a reverse proxy).
- **Gemini free-tier limits** are modest and change over time (roughly 10–15 requests/min, a few hundred to ~1,500/day for Flash models, per third-party reports; check AI Studio for real numbers). Kairos must budget requests and degrade gracefully on HTTP 429.
- **Free-tier data use:** Google may use free-tier prompts to improve products. Only public market data goes into prompts; **the owner's holdings/quantities are never sent to Gemini** (designer's call).
- **Versions:** latest stable libraries, LTS runtimes, avoid day-one majors; commit lockfiles (owner's global policy).

## 4. How it gets made

### Stack (designer's call)
| Layer | Choice | Why |
|---|---|---|
| Backend | **Python + FastAPI** | Best free ecosystem for market data and text (yfinance, pandas, feed parsing). |
| Frontend | **React + Vite + TypeScript**, TanStack Query, a lightweight charting lib | Owner's home turf; no SSR/SEO needs, so no Next.js. |
| Storage | **SQLite** in a mounted volume | Single user; caches articles, stores readings, watchlist, track record. |
| LLM | **Gemini (Flash-class model) via official Google GenAI SDK** | Free tier; structured JSON output. |
| Packaging | **One Docker image** (multi-stage: build frontend, serve static files from FastAPI) + `docker-compose.yml` | One container, one port, plug-and-play. |
| Scheduling | In-process scheduler (e.g., APScheduler) inside the same container | No separate cron container needed. |

Model ID is configured via env var so it can be swapped when Google changes free-tier models.

### Data sources (designer's call)
| Need | Source | Notes / risk |
|---|---|---|
| Prices, history, key numbers, ETF info & top holdings | **yfinance** (Yahoo) | Free, unofficial; can break. Isolate behind an adapter. |
| Company news | **Finnhub** free tier (company-news endpoint) | Requires free API key. |
| General / extra news | **Google News RSS** (query by ticker + company name) | No key. |
| Filings | **SEC EDGAR** (8-K, 10-Q/10-K recent filings) | Free; requires a descriptive User-Agent with contact email set in `.env`. |
| Earnings dates | **Finnhub** earnings calendar | Free tier. |
| Ex-dividend dates | yfinance | |
| Macro events (FOMC, CPI) | Static yearly calendar file shipped with the app, editable | No reliable free API needed; update yearly. |
| Reddit | **Optional add-on, off by default** | New Reddit API access requires approval and reportedly closed to new requests on 2026-10-31. Kairos must work fully without it. If enabled, low-volume public RSS only. |

Each source sits behind a small adapter with a common shape (`fetch(ticker) -> items | error`) so a broken source can be swapped or disabled independently.

## 5. v1 features (owner agreed)

### 5.1 The reading (core)
For a ticker, a reading contains:
- **Header:** ticker, name, last price, day change, type (stock/ETF).
- **Lean:** bullish / neutral / bearish + confidence (low / medium / high), or **"not enough signal"**.
- **What's driving it:** 2–5 bullet drivers, each with linked source(s).
- **Bull case / bear case:** short paragraphs, each claim sourced.
- **Price chart** (e.g., 6–12 months) with 50/200-day averages.
- **Sources list:** count and links to every article/filing used; timestamp of the reading.
- **Data health:** which sources succeeded/failed for this reading.

### 5.2 "Should I add more?" view (holdings and any ticker)
Computed in code: price vs 50-day and 200-day moving averages, distance from 52-week high/low, recent volatility (e.g., 30-day), with a plain-language label such as "stretched above averages" / "near long-term average" / "well below recent range". Not a buy signal — context for a long-term buyer.

### 5.3 Upcoming events
Next earnings date, next ex-dividend date, and upcoming FOMC/CPI dates within ~30 days. Flag when earnings are within ~7 days.

### 5.4 Hype warning signs (shown on every reading, prominent on search-bar lookups)
Computed in code, each shown as a flag with its value:
- Attention spike vs the ticker's own recent baseline (article count from news sources; plus Reddit mentions only if that add-on is enabled), **without** corresponding substantive news (substance judged by the LLM from article content and reported back as a field).
- Small market cap (threshold configurable; default: under ~$300M = micro-cap flag).
- Large recent price spike (e.g., > ~30% in 5 trading days).
- Not listed on a major US exchange (OTC/pink).
- Low average volume / low price ("penny stock").

### 5.5 Quick numbers
- **Stocks:** market cap, P/E (trailing/forward), P/E vs a sector reference, revenue growth, profit margin.
- **ETFs:** expense ratio, AUM, top holdings with weights.

### 5.6 Track record
Every reading is saved with its lean, confidence and the price at reading time. A daily job fills in price change at **+1, +5 and +20 trading days**. A panel shows, per ticker and overall, how leans compared with what happened (e.g., bullish leans: % followed by a rise over 20 days). Must clearly show sample size so a handful of readings isn't over-interpreted. (Designer's call: also show the same-window move of VOO as a baseline, so "bullish lean followed by a rise" isn't just the whole market rising.)

### 5.7 Discover (sidebar section)
v1 suggestions come from:
- Tickers with an unusual **news-volume spike** among a configurable universe (default: S&P 500 + Nasdaq-100 constituents + a short ETF list).
- **"Similar to what you hold"**: ETFs/stocks sharing sector or top holdings with the owner's holdings.
Each suggestion shows *why* it was suggested. (Designer's call: the spike scan uses only Finnhub article counts, no Gemini, paced under Finnhub's free per-minute limit; for a ~600-ticker universe this takes several minutes in the morning job, which is acceptable.) Discover runs on the morning schedule, not on every page load, and must respect the Gemini budget (suggestions are ranked in code; full readings only generated when the owner clicks).

### 5.8 Watchlist and holdings
The owner manages two lists in the UI: **Holdings** (the owner's current positions) and **Watching**. v1 stores tickers only; quantities are optional and never leave the machine.

## 6. Later (owner agreed — not in v1)
1. Thesis notes: one line per holding; Kairos flags news that contradicts it.
2. True exposure: look-through of ETF holdings (e.g., NVDA is a top holding in both VOO and QQQ).
3. Side-by-side compare (e.g., QQQ vs SMH).
4. Ask-about-this-report chat.
5. Discord/email daily summary and price alerts (owner: dashboard first, summaries later).
6. VPS deployment (owner: later).

v1 must not paint these into a corner (e.g., store readings and sources in a way a later summary/chat can reuse).

## 7. How a reading is produced (designer's call)

1. **Collect:** run source adapters in parallel for the ticker (news window: last ~7 days, configurable). For ETFs, collect news for the **top ~10 holdings weighted by fund weight** plus general market news, instead of the ETF ticker alone.
2. **Clean:** de-duplicate, drop off-topic items, trim to headline + summary/lead, cap total input size.
3. **Compute in code:** price context (5.2), events (5.3), hype signals (5.4), quick numbers (5.5).
4. **One Gemini request per ticker** with the cleaned articles + computed numbers, requesting **structured JSON**: lean, confidence, drivers (each with source IDs), bull case, bear case, "substantive news?" flag, "not enough signal" flag. The prompt forbids introducing facts not present in the supplied sources.
5. **Validate:** schema-check the JSON; drop any claim citing a source ID that wasn't supplied; on failure, retry once, then show the reading with an "AI summary unavailable" state while still showing all computed sections.
6. **Store** the reading and its sources in SQLite; display.

**Refresh policy:** holdings + watchlist refresh automatically each morning (designer's call: time configurable via env, default 07:00 in the timezone set by `TZ`, so overnight US-session news is included when the owner wakes). Search-bar lookups run on demand. Readings are cached for a few hours (configurable); a manual "refresh" button bypasses the cache but shows the request budget.

**Request budget:** track Gemini requests per minute/day in SQLite; queue and pace requests to stay under configured limits; on 429, back off and surface "AI budget reached — computed sections still shown".

**Why Gemini, not Grok:** as of late 2026, reports indicate xAI ended free monthly API credits (April 2026); Grok API is effectively paid-only. Gemini's free tier fits one-reading-per-ticker-per-day usage comfortably.

## 8. Screens (owner chose layout A)

- **Top bar:** "KAIROS" + search input ("Check any ticker…").
- **Left sidebar:** *My Holdings*, *Watching*, *Discover ✦* — each row shows ticker + lean pill (Bullish / Neutral / Bearish / Hype warning / Not enough signal). Add/remove tickers here.
- **Main panel:** the full reading (§5.1) with sections for "Should I add more?", events, hype flags, quick numbers, drivers, bull/bear, sources, data health.
- **Track record:** reachable from the main panel (per ticker) and as an overall view.
- **Settings:** schedule time, cache duration, Reddit add-on toggle, thresholds, model ID display, Gemini budget usage.
- A short, non-preachy footer note that readings are research input, not financial advice.

## 9. Security and operations
- API keys live only in `.env` (gitignored); a committed `.env.example` documents each variable. Keys are used server-side only and never sent to the browser.
- Bind to `127.0.0.1` by default on the Mac; VPS later goes behind the existing reverse proxy with authentication (exact method decided at VPS time).
- SQLite file in a named volume / bind mount so container rebuilds don't lose history; document how to back it up (copy the file).
- Container healthcheck endpoint; restart policy `unless-stopped`.
- Respect source terms and rate limits (SEC User-Agent, Finnhub limits, polite RSS polling).

## 10. Left to the builder
- Exact library versions (per the version policy), charting library, UI component approach and styling.
- Database schema and migration approach (keep it simple; SQLite-friendly).
- Exact prompt wording, JSON schema field names, and article-trimming heuristics.
- Exact thresholds' defaults where marked "e.g." (keep them configurable).
- Sector reference for P/E comparison (any reasonable free source or computed from the universe).
- Test strategy (expect unit tests for computed metrics, hype flags, JSON validation, and adapter error handling; source adapters mocked in tests).
- Project folder structure (layer-based per owner's defaults: e.g., `backend/` with routes/services/adapters, `frontend/`).

## 11. Known risks
- **yfinance breakage** — mitigated by the adapter layer and data-health display.
- **Gemini free-tier changes** (quota cuts, model retirement) — model ID and limits in config; computed sections work without the AI.
- **Reddit access** — treated as optional from day one.
- **Signal quality** — sentiment-based leans may simply not be predictive; the track record exists to reveal this honestly rather than hide it.
